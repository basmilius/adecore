# Public entrypoints

`@adecore/agents` exports per-file modules using `./*`, plus a `./*.json` pattern for JSON data. There is no `@adecore/agents` root entrypoint. Import the following suffixes without `.ts` or `.js`; the `source`, `types`, and default conditions select the appropriate file.

These preserved subpaths are supported consumer imports even when their names look internal. A wildcard matches only a file included in the package; it does not promise arbitrary nonexistent modules. Tests are excluded from the artifact.

## Data assets

Import model catalogs as `@adecore/agents/providers/claude-models.json` or `@adecore/agents/providers/codex-models.json` with a JSON import attribute where required by the runtime. `usage/prices-snapshot.json` contains the bundled price fallback. Validate replacement catalog data with `ModelCatalogDataSchema`; the current catalog is package data, not a promise of provider access.

Captured JSON/JSONL protocol fixtures and fake CLI modules are copied into compiled artifacts for compatibility checks. They are evidence and test data, not live accounts or an executable installer. Prefer the exported fake functions rather than depending on the path of an individual captured fixture.

## Runtime boundary

Use `@adecore/agent-contracts` in a browser, preload, or renderer when you only need shapes. Keep backend modules in Node/Bun or an Electron main/utility process. Modules that happen to be pure helpers do not make the backend package a browser distribution. For a browser client use the contracts plus [agent views](../agents-react/) or a [consumer transport](./transport).

Build contracts before agents for default JavaScript and declarations. Linked development selects `source`; a compiled consumer needs the built `dist` files, including catalogs. The backend has no CSS, theme, or translation assets to initialize.
