### Embedded languages during edits

A `LineTokenizer` may provide `prepare(text)` to load embedded grammars named by edited text. It resolves to `true` when a load can invalidate earlier states; `stale()` then reports the rebuild once. Shiki tokenizers recognize Markdown and MDX fence info and `lang` attributes in Vue, Svelte and Astro. Ordinary prose does not load fence languages. Concurrent documents share each language load.

The editor checks declarations in edited lines 200 ms after the last edit, with one preparation running at a time. Undo, redo and external edits use the same path. A buffer above 64 KiB triggers one scan of the current document. After a grammar rebuild, coloring starts at the first line while previous colors stay visible. External `setLineTokens` providers pause preparation; clearing the provider schedules a full scan. Theme changes and disposal ignore late preparation results.

### Worker request lifecycle

`@adecore/editor/worker-client` exports `createWorkerRequestClient`, `WorkerRequestError`, `WorkerRequestErrorKind`, `WorkerRequestPort`, `WorkerRequestOptions` and `WorkerRequestClient`. It owns one active request and one pending request; the newest request supersedes both. Requests are posted in a microtask. A deadline starts before posting and includes worker startup; timeout terminates the worker. Load failures before its first message remain unavailable. `release()` frees the worker and lets the client restart; `dispose()` is final.

`request(inputFactory, deadline?, validate?)` allocates a monotone id after validation. Protocol adapters supply response validation, deterministic failures that keep the worker alive, optional message preparation and a stop hook for snapshot caches. A `{ type: 'ready' }` reply marks successful startup without completing a request. Use a separate client for independently cancellable work. The search client uses this lifecycle without changing its public protocol.

`editor.applyEdits(edits, { mapSelections })` accepts an optional function that maps each current selection, as a start-before-end range, to its place in the resulting text; each selection keeps its direction, and a collapsed selection stays collapsed only when its mapped range is empty; otherwise it selects the mapped range. When the edits leave the text unchanged, nothing is applied to the selections. The text and selections are emitted together and recorded in one undo step, so redo restores those selections. Omitting the option keeps the existing affinity. Read-only editors still refuse the entire operation.

`{ mergeUndo: true }` joins the edits to the undo step before them when the text is exactly as that step left it, so one undo takes both back; a host uses it for a change that follows from the person's last edit, such as formatting after a typed character. Otherwise the edits are a step of their own. `EditorTextChange.typed` marks a change a person's typing made though it ran as a command, as Enter does; the `source` of a change from the keyboard stays `'input'`.

`editor.isReadOnly()` says whether the editor refuses edits right now, the state `setReadOnly` and the `readOnly` option set. It is optional on the `Editor` interface, so a host that wraps an older editor checks `editor.isReadOnly?.() ?? false`.

### Compatibility

`Editor` gained `setInputPopup`, `announce`, `setLineLabels` and `setMessages`, and `isReadOnly` as an optional method. `EditorMessages` gained `fold` and `unfold`. An implementation of `Editor` outside this package has to add the four required methods; code that builds an `EditorMessages` value in full has to add the two keys, or build a `Partial<EditorMessages>`, which is what the `messages` option takes.

`toggleRenderedDocs` and `wrapWithAbbreviation` are `KEYMAP` commands that a full `Keymap` written by a host may leave out (`OptionalKeymapId`); `chordOf` then reads the built-in chord. `Editor` gained `getBaseLineHeight` as an optional method, and `EditorReplacement` gained the optional `enterable` and `onReveal`. Outside macOS, a Ctrl+Alt press that types a character other than the key's own (AltGr+Q typing `@`) no longer matches a chord that names both; `typesInsteadOfChord(event, apple)` from `@adecore/editor/keymap` is that test, and keys that type nothing, such as arrows, always match.

`increaseFontSize`, `decreaseFontSize` and `resetFontSize`, and `sortLines`, `reverseLines`, `uniqueLines`, `convertIndentsToSpaces` and `convertIndentsToTabs`, are `KEYMAP` commands without a chord, and `OptionalKeymapId`s, so a full `Keymap` written before them stays valid. `Editor` gained `setTodoWords`, `setFontSize`, `getFontSize`, `onFontSizeChange`, `cleanUpWhitespace` and `markSaved` as optional methods.

`moveStatementUp` and `moveStatementDown` (`Mod+Shift+ArrowUp` and `ArrowDown`) are `KEYMAP` commands and `OptionalKeymapId`s, and `EditorCommand`s that `execute` runs; `CommandOptions` gained `structure`, and the editor view reads it from `structureRanges()`, the folding ranges with a server's hints, whether or not the folds are drawn. On macOS `selectTextStart` and `selectTextEnd` lose their chord (`Meta+Shift+ArrowUp` and `ArrowDown`), which is Move Statement as in IntelliJ; `Mod+Shift+Home` and `Mod+Shift+End` still select to the text edges. To keep the old chords, pass `resolveKeymap({ selectTextStart: { mac: 'Meta+Shift+ArrowUp' }, selectTextEnd: { mac: 'Meta+Shift+ArrowDown' }, moveStatementUp: { mac: null }, moveStatementDown: { mac: null } })`. `completeCurrentStatement` is a `KEYMAP` command (`Mod+Shift+Enter`) and an `OptionalKeymapId`, and an `EditorCommand` that `execute` runs. `nextChange` and `previousChange` are `KEYMAP` commands and `OptionalKeymapId`s too, run by `runCommand` as view commands. `methodUp`, `methodDown`, `codeBlockStart`, `codeBlockEnd`, `codeBlockStartWithSelection` and `codeBlockEndWithSelection` are `KEYMAP` commands and `OptionalKeymapId`s, so a full `Keymap` written before them stays valid. `Editor` gained `setDeclarations`, `onNavigate` and `hasFocus` as optional methods, and `CommandOptions` gained `indentGuides`. Two defaults changed. Off macOS, `shrinkSelection` is `Ctrl+Shift+W` and no longer `Alt+ArrowDown`, since `Alt+ArrowUp` and `Alt+ArrowDown` are Method Up and Down there. To keep the old chord, pass `resolveKeymap({ shrinkSelection: { other: 'Alt+ArrowDown' } })` and give `methodDown` and `methodUp` other chords there.

`ProjectLanguage.acquire` takes a fourth parameter, `AcquireOptions` (`{ serve?: boolean }`, true by default), and a language service an app wrapped must forward it. `ProjectLanguage.openEditors()` lists the editors that hold a document. `EditorLanguageOptions` gained `serve`, and `EditorLanguage` gained `served` and `service`; `@adecore/lsp` exports `unservedLanguageService`. Every feature now asks `language.service` and no longer `project.service`, so a document acquired with `serve: false` never reaches the project's service. Upgrade path: an override of `acquire` passes the options on to `super.acquire`, and an app that read "an `EditorLanguage` exists" as "a language server serves this document" reads `language.served` instead, since an `EditorLanguage` can now exist for a plain-text file. `project.service.onDiagnostics` stays on the project.

`hippieCompletion` (`Alt+/`) and `hippieBackwardCompletion` (`Alt+Shift+/`) are `KEYMAP` commands and `OptionalKeymapId`s, and `EditorCommand`s that `execute` runs. `CommandOptions` gained `wordSources`, `DocumentModel` gained `hippieSource`, and `Editor` gained `setWordSources` as an optional method.

`lastEditLocation` (`Mod+Shift+Backspace`) and `nextEditLocation` (no chord) are `KEYMAP` commands and `OptionalKeymapId`s that the language side of `@adecore/editor-react` runs, not `runCommand`. `LanguageHost` gained `editHistoryLimit`, `ProjectLanguage` gained `edits` (an `EditLocations`), and `HistoryFeature` gained `lastEdit` and `nextEdit`.

`pasteFromHistory` (`Mod+Shift+V`) is a `KEYMAP` command and an `OptionalKeymapId` that the language side of `@adecore/editor-react` runs, and `pasteAsPlainText` (`Mod+Alt+Shift+V`) is a `KEYMAP` command, an `OptionalKeymapId` and an `EditorViewCommand` that `runCommand` runs. `Editor` gained `onCopy` and `paste` as optional methods, with `EditorCopy` and `EditorPasteOptions`, and `@adecore/editor` exports `rememberCopy(text, wholeLines)`, which makes a text paste back as whole lines like the last copy of bare carets. `LanguageHost` gained `clipboard`, `ProjectLanguage` gained `clipboard`, and `EditorLanguage` gained `pasteHistory`. `PickSpec` gained `filter`, `multiple`, `acceptMany` and `remove`, `PickRow` gained `search`, `PickPreview` gained `kind`, and `PickView` gained `query` and `chosen`, so a host that builds a `PickView` by hand adds those two.

`typeHierarchy` is a `KEYMAP` command and an `OptionalKeymapId`. `setInlayHints` takes an optional `owner`, so the hints of several owners stand side by side, and `EditorInlayHint` gained `swatch`.

`Editor` gained `placeAt`, `postfixOperands`, `surroundShape` and `unwrapTargets` as optional methods, so a host that wraps an older editor checks for them first. They answer from the text and the language of the editor, and `FakeEditorEngine` answers them too. `placeAt(position)` returns an `EditorTextPlace`, the `language` the position is written in and its `kind` (`code`, `comment` or `string`). `postfixOperands(dot)` returns the `EditorPostfixOperand` values that end right before a dot, innermost first, each with its `range` and whether it starts a `statement`. `surroundShape(range)` returns an `EditorSurroundShape`, with the trimmed `range`, `statements` and `expression`, or `null` for a blank range. `unwrapTargets(position)` returns the `EditorUnwrapTarget` values around a position, innermost first, each with its `kind`, the `range` of the construct and the `edits` that `applyEdits` takes as they are. The rules are those of the [lexical queries of editor-core](/editor-core/api#lexical-queries).

`insertLiveTemplate`, `surroundWith`, `surroundWithLiveTemplate`, `unwrap` and `saveAsLiveTemplate` are `KEYMAP` commands and `OptionalKeymapId`s. The first four are bound to `Mod+J`, `Mod+Alt+T`, `Mod+Alt+J` and `Mod+Shift+Delete`, as in IntelliJ; the last has no chord.

`commentSyntax(language)` returns the `CommentSyntax` of a language id, its `line` comment marker and its `block` pair (`open` and `close`), each `null` where the language has none; an id nothing knows has neither. [Surround With](/editor-react/templates#surround-with-and-unwrap) writes its region comments in it.

### Breaking: Wrap with Abbreviation has no default chord

`wrapWithAbbreviation` lost its default chord, `Mod+Alt+J`, to `surroundWithLiveTemplate`. In IntelliJ that chord is Surround with Live Template, and Emmet is a row of that list. Wrapping still works: the command is still answered when a host binds a chord to it, and `language.markup.startWrap()` opens it for a menu.

- A host that prints or requires the chord of `wrapWithAbbreviation` gets `null` from `chordOf` now. Read `surroundWithLiveTemplate` instead, which is the chord that reaches Emmet.
- A host that wants the field on a chord of its own sets `wrapWithAbbreviation` in the overrides it gives `resolveKeymap`, for example `{ wrapWithAbbreviation: { mac: 'Mod+Alt+J', other: 'Mod+Alt+J' } }`, and moves `surroundWithLiveTemplate` to another chord, since no two commands may share one.
